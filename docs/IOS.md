# iPhone app

What it is: the Android app's screens on iPhone. The UI and the view model are shared Kotlin (Compose Multiplatform, module `:shared`: `app.expenses.ui.*`, `LedgerViewModel`, `ExpensesRoot`); the iPhone app (`iosApp/`) is a thin SwiftUI shell that shows the shared root in one view controller. Built with Xcode 27.1, Kotlin 2.4.20, Compose Multiplatform 1.12.1.

## How the pieces fit
- `shared/src/commonMain`: every screen, `ExpensesRoot(viewModel, host: RootHost)`, `interface Platform` (what the OS must provide).
- `shared/src/iosMain`: `IosPlatform` (database in Application Support under iOS Data Protection, files by URL, attachments, statements, app lock), `IosAppLock` (the shared `LockGate` with Face ID / Touch ID / passcode through LocalAuthentication; covers the app-switcher snapshot while the lock is on), `IosBackupCipher`, `IosXlsx` (zip with zlib + NSXMLParser, same rules as the Android reader), `IosCore` (the process-wide platform and database owner, also used by background intents), `IosCapture` (what the Shortcuts intents call), `MainViewController(host)`, the iOS actuals of the UI hooks (`ui/PlatformHooks.ios.kt`: Files picker, haptics, back gesture).
- `iosApp/Sources`: `ExpensesApp.swift` (window and `UIViewControllerRepresentable`), `CryptoServices.swift` (the only Swift-only pieces: PBKDF2 and AES-256-GCM, through CryptoKit/CommonCrypto, behind `IosHostServices`), `Intents.swift` (the App Intents: Capture bank message, Add expense, and the Shortcuts/Siri phrases).
- Passphrase-protected backups use the Android file layout (`EXPENC1\n`, iterations, salt, nonce, AES-GCM with the header as authenticated data). The layout is written once, in Kotlin (`IosBackupCipher`); Swift only supplies the primitives, so the formats cannot drift. `tools/backup_interop/Interop.java` repeats the Android `BackupCrypto` steps with javax.crypto: the fixture `iosApp/Tests/Fixtures/android-made.expbak` was written by it and opens on the iPhone code (unit test), and the file the iPhone test writes opens in it (`tools/ios_build.sh interop`).
- Saving a file (export, backup): iOS shares a file that exists, so the shared "pick a place, then write" order becomes "write a staging file, then show the share sheet" (Save to Files, AirDrop, Mail...). Opening a file (statement, backup, attachment) uses the Files picker; picked files are copied to the temporary folder first.

## What works on iPhone
The screens of the Android app are shared code, so all are in the app. Opened and looked at in the simulator: Home, add, Search with the bulk bar, Reports, More, To review, Capture from texts, Accounts, Categories (both tabs), Repeating expenses, Calendar, Lent and borrowed, Bills, Appearance, Customise home, Currency, Notifications, App lock, Privacy, Your data, the guide; the similar-entries offer. Not yet exercised on iOS: Hide amounts, Budgets, importing a real statement file, restoring a backup, attachments, and a real Face ID / passcode prompt (the simulator has none enrolled). The list: Home, add/edit (with attachments), Search with bulk edit and saved searches, Reports, Calendar, Accounts, Categories (expense/income), Recurring, Bills, Budgets, Loans, Appearance, Customise home, Currency, Hide amounts, Privacy, Your data (CSV/Excel export, statement import for CSV and .xlsx, backup and restore with optional passphrase), the guide, the similar-entries offer. App lock works through the system prompt.

## What is not on iPhone (and how the app says so)
- Reading texts and other apps' notifications: iOS gives apps no access to either. Bank messages reach the To review inbox another way, see "Bank messages on iPhone" below.
- Reminders (bills due, tracked bills, card due dates, budget alerts, weekly recap): local notifications, no server. `IosNotifications` (iosMain) runs the same `NotificationService.check` Android's hourly work runs (prefs, quiet hours, the record of what was shown, repeating items set to post by themselves) and shows the notices through UNUserNotificationCenter; it runs when the app comes forward, when it goes to the background, and from a BGAppRefreshTask (`app.expenses.tracker.ios.refresh`, UIBackgroundModes fetch; iOS decides if/when it runs, so this is best effort). Because of that, bill and card reminders for the next 7 days are also handed to the system ahead of time (`NotificationService.plannedFor`, calendar notifications at the reminder hour); each check replaces them. Budget alerts, the recap and bills found in messages need the app to run. The permission is asked from Settings > Notifications ('Allow notifications'); after a refusal the button opens the app's page in iOS Settings. Hide amounts removes figures from every reminder; found/tracked bills (and everything under Hide amounts) use a private category, so with iOS 'Show Previews' set to hide, the lock screen only says 'Open the app to see it'. Tapping a bill-found or tracked-bill reminder opens Bills; others open the app. UI test: `NotificationsUITests` (permission dialog accepted, a made-up bill due today is delivered, one due in 2 days is pending; launch argument `-notify-debug-run`). Not testable on the simulator: when/whether the background refresh fires.
- Automatic export to a folder: `supportsAutoExport` is false (iOS has no background scheduling that would keep it reliable); the Data screen says so.
- Home-screen widget, Quick Settings tile, launcher shortcuts: not built.
- A separate database key: the file relies on iOS Data Protection (readable after the first unlock).

## Bank messages on iPhone
iOS lets no app read text messages or other apps' notifications, so Android's automatic capture (`SmsReceiver` + `Capture.ingest`) cannot exist here. Two things iOS does allow stand in for it; both end in the same To review inbox, and nothing reaches the ledger until the person adds it there.

**1. A Shortcuts automation (automatic).** `iosApp/Sources/Intents.swift` defines the App Intent `CaptureBankMessageIntent` ("Capture bank message": `message` text, optional `sender`) and `AddExpenseIntent`, and an `AppShortcutsProvider`, so both appear in the Shortcuts app and in Siri with no setup. The person makes one Personal Automation: Shortcuts > Automation > New Automation > Message > Message Contains (words such as `debited`, `credited`, `Rs.`, `INR`; Sender left empty) > Run Immediately (Notify When Run off) > New Blank Automation > add action Capture bank message > Message = Shortcut Input, optionally Sender = Shortcut Input's Sender. The "Capture from texts" screen shows these steps (flag `Platform.supportsShortcutsCapture`, true only on iOS), an Open Shortcuts button (`shortcuts://` through `Platform.openExternalUrl`), how to send a test message, what is done with the words and the limits below.
- The intent runs in the app's own process, started in the background by Shortcuts with no window. `IosCore` (iosMain) is the once-per-process owner of `IosPlatform` and the `AppContainer` (one database connection per process, whether or not a screen exists; the app's view model is built on it), and `IosCapture` is what Swift calls: `captureMessage(host, sender, message)` and `addExpense(host, amountText, note, categoryName)`. Both return a short sentence (`Captured, review it in Expenses`, `Ignored: not a bank transaction`, `Ignored: a one-time password`, ...) that Shortcuts shows or Siri speaks.
- The pipeline is `MessageIngest.ingest` (shared commonMain, no java.*): the logic of Android's `Capture.ingest` written with kotlinx-datetime, kotlin.uuid and the pure-Kotlin `Sha256`. The sender is judged before the words are read; a bank transaction from an allowlisted header (built-in list plus the person's extra sender names) becomes a pending `InboxItem`; a bill becomes a `Bill`; an OTP, a person's number, a declined payment, a non-transaction or an unlisted sender is only counted (`recordEvent`; the words are never stored). The Android class `Capture` is untouched.
- Time and duplicates: Shortcuts hands over no arrival time, so the item is stamped with the time it reached the app and the fingerprint is the calendar day plus the normalised words (not the sender, not the time). The same text handed over twice, or by the automation and again by a paste, is one item (`DUPLICATE`, counted as "Same text seen again"). Two identical texts on one day (no reference, no time in the words) would also merge: the conservative side, since a missed duplicate costs the person a wrong entry and a merged pair costs a glance at their bank app.
- After a kept item, `MessageIngest.changes` is bumped; `IosPlatform.captureChanges` is that flow, so an open To review and the Home banner refresh.
- `AddExpenseIntent` ("Add expense": amount text such as `250`, `99.50`, `₹250`; optional note; optional category name): saves through `EntryActions.save` in the account and (unless one is named) the category used last, with no screen. A category name that does not exist is refused ("There is no expense category called X") rather than filed somewhere else.

**2. Paste (manual).** On iOS only, To review has `Paste a bank message` (tag `inbox_paste`): it reads the clipboard through `Platform.readClipboardText()` when the button is pressed, never otherwise (iOS asks the person to allow the paste when the text comes from another app). With an empty clipboard, or with "Type or paste it here instead", a text box takes the words. The result is shown in place (`Captured, review it in Expenses: Debit of ₹250.00 from HDFC Bank`, or why not). Pasted words are processed on the phone only.
- A pasted text has no sender, and the classifier's allowlist needs one. The conservative rule (`PasteRules`): the words must carry their own evidence. (1) A known bank, card issuer or biller from the built-in list is named in the text (`HDFC Bank`, `SBI`, `BESCOM`, or the header itself, `HDFCBK`): the text is judged as if it came from that header, so the bank-specific rules and the issuer name apply. (2) Otherwise it must have all of: a rupee amount (Rs, INR, ₹), a word saying money moved (debited, credited, withdrawn, deposited, spent) and an account or card mask (`a/c XX1234`, `card ending 4321`); it is then shown as "Bank message". Anything else is counted as "not a bank transaction" without being parsed. The same rule applies to an automation that passes no Sender. A friend's "I sent you Rs 500" has none of the evidence. Texts are cut at 4,000 characters.
- If the automation does pass a Sender, it is judged first exactly as on Android: a phone number is a person and is ignored without the words being read, an unlisted header is counted under "Senders not on the list" with the "This is my bank" button. A bank saved in Contacts shows up under the contact's name, which is read as a person, so the guide says Sender is optional and to leave it empty when that happens.

**Capture health** (`How capture is doing`) is the same screen; with the flag on it has no switch or permission to be missing, and its advice talks about the Shortcuts automation instead of battery saver. Pasted messages that carry no header are recorded under the name `PASTED` (counts only).

**Limits, as the setup screen says them.** iOS may show a banner when the automation runs, even with Run Immediately. It works for messages in the Messages app (SMS, iMessage, RCS), not for WhatsApp or other apps. A message from an unknown sender, or one filed under Unknown Senders or Junk, may not start the automation, and a bank's alphabetic header is often treated that way; transaction texts can still be pasted. The app's data is readable only after the first unlock after a restart (iOS Data Protection), so a message that arrives before then is not captured. There is no iOS counterpart of notification capture (Google Pay, PhonePe) and none of the bill reminder at the moment a bill text arrives; a captured bill is on the Bills page and a reminder follows when the reminders check next runs.

**Tests.** `iosApp/Tests/CaptureTests.swift` (the intent and the Kotlin entry with made-up senders such as `AX-HDFCBK-S`: captured, same text twice, OTP / person / notice ignored, sender-less rules, Add expense, clipboard) and `iosApp/UITests/CaptureUITests.swift` (a message handed in at launch with `-ingest-message "sender|words"` through the same Kotlin entry shows in To review; OTP and personal text leave only counts; the same text twice is one item; paste flow; the setup guide).

## Build and test
- `./gradlew :shared:assembleSharedXCFramework -PenableIos=true` builds `shared/build/XCFrameworks/release/Shared.xcframework` (the Kotlin/Native link needs the big heap set in `gradle.properties`: `kotlin.native.jvmArgs`).
- `tools/ios_build.sh test`: framework, XcodeGen project, then unit tests (backup format) and UI tests on the iPhone 17 simulator. The UI tests find Compose elements by `testTag`: on iOS every testTag is an accessibility identifier, so they use the same tags as the Android device tests. Launch arguments for tests: `-reset-data` (empty ledger), `-dismiss-welcome`, `-ingest-message "sender|words"` (hands one message to the Kotlin entry the Shortcuts intent uses; may be given several times). Screenshots of the screens visited are written to `/tmp/ios-shots`.
- `tools/ios_build.sh interop`: the iPhone-written backup read back by the Java reference.
- `tools/ios_build.sh ipa`: signed Release build, `~/Desktop/Expenses-iOS-<version>-test.ipa`. `tools/ios_build.sh build`: simulator and device builds without packaging.
- The app icon is generated by `swift tools/make_ios_icon.swift <out.png>` from the Android adaptive icon's shapes (no alpha channel).
- Requires `brew install xcodegen`. Version 0.1.0 (1), bundle id `app.expenses.tracker.ios`, display name Expenses, iPhone only, iOS 17 and later.

## Installing on the iPhone (free Apple ID signing)
1. The build is signed with the Apple Development certificate of team 9V2G5RH624 and a provisioning profile that lists one device (UDID 00008150-000855380C99401C). It expires 7 days after it was made (a free account); after that rebuild and reinstall. A paid Apple Developer account makes it a year and allows TestFlight and the App Store.
2. On the iPhone: Settings > Privacy & Security > Developer Mode > On (it restarts).
3. Install: connect the iPhone by cable, open Xcode > Window > Devices and Simulators, select the phone, press + under Installed Apps and choose the .ipa. (Or `xcrun devicectl device install app --device <name> Expenses.app`.)
4. First launch: Settings > General > VPN & Device Management > the developer app > Trust.

## App Store checklist
- `PrivacyInfo.xcprivacy` declares no tracking and no collected data, and the required-reason APIs the app and its frameworks use: UserDefaults (CA92.1), file timestamps (C617.1), system boot time / uptime (35F9.1). No disk-space API is used by the app's own code.
- `NSFaceIDUsageDescription` is set. Export compliance: the app uses AES-256-GCM only for the user's own backup files; whether to declare that exempt (`ITSAppUsesNonExemptEncryption`) is the owner's answer to give in App Store Connect, so the key is not preset.
- The icon is 1024x1024 without alpha. Screenshots, description, privacy policy URL and age rating are still to be made in App Store Connect.
